# Codex and Claude Accounts

OpenUsage reads Codex and Claude logins already present on this Mac. It discovers the standard CLI homes, supported Swap profiles, and supported Claude Desktop organizations. To connect another CLI profile, open **Customize → Accounts**, choose **Add Profile…** under Codex or Claude, and select its directory. OpenUsage requires a readable account identity and access token before adding the profile. Sign in with the CLI if either is missing.

Profiles with the same account identity appear as one account. You can detach a selected directory without removing the account when another source is still connected. Alias and account order are saved on this Mac. New accounts use the provider's default metrics and placement; they have no menu bar stars until you choose them.

With one known account, the dashboard keeps the usual provider card. With two or more enabled accounts, it shows one provider section with a summary and a collapsible card for each account. If several Codex accounts are known but only one is enabled, the combined Codex summary still appears because shared logs cannot be assigned to the visible card. Account cards start open and remember their collapsed state. The summary starts with accounts that still have Session or Weekly quota, Today spend, and Last 30 Days spend. Choose **More** for other compatible totals; **Customize → Accounts → Provider Summary** can keep an optional total visible or star a summary metric for the menu bar.

The summary adds dollar and token values only when they have the same unit and period. A quota percentage has no known absolute capacity, so Session and Weekly show how many accounts still have quota. Reset times remain on their account cards. When an account fails, the summary labels its totals incomplete and keeps the other accounts' results.

**Remove Account** stops monitoring that account and keeps it in **Removed Accounts**. Discovery does not add it back automatically. Use **Add Again** to reconnect it; if its login or selected directory is gone, repair the CLI session or choose the directory again. The account's local spend history stays available in the archive. **Delete History** deletes its saved history on this Mac and excludes older local log days if the account is added again. Other Macs keep their own history. The dashboard's total uses enabled, connected accounts where history can be assigned to them. Multi-account Codex contributes one combined local estimate, which can include activity from accounts that share those logs but are now disabled.

**Reset All Customization** restores metric layout and stars, and rechecks connected account credentials. It keeps selected profile directories and aliases. Changes made in Accounts appear immediately; external CLI changes appear on the next refresh.

Selected Claude profiles read their own `.credentials.json` or directory-specific Keychain entry. OpenUsage does not rotate their tokens; sign in with the matching Claude CLI profile when a token expires. A selected Claude profile needs both its account and organization identity. Selected Codex profiles need an `auth.json` that identifies both the workspace and signed-in user; a Keychain-only profile cannot be identified from a chosen directory. With multiple Codex accounts, local Codex logs appear as combined estimated spend in the provider summary. OpenUsage cannot assign that spend to individual accounts, so account cards show quota and credits without spend or trend rows. The summary labels the combined source as information; only missing account data triggers an incomplete warning.
